## Recording rules

Each completed run records config, source commit, manifest/archive hashes, seed,
input resolution, training steps, device, parameter count, training history,
checkpoint hash, selection rule, metric definitions and limitations. New runs also
record process peak RSS, CUDA peak allocated/reserved bytes where available, and
wall time with an explicit scope. Missing historical resource measurements remain
missing; they are not reconstructed from current hardware.

Failed or interrupted runs retain their logs and status. Pending results are null,
not zero. A completed-run receipt hashes the source result files. CSV and Markdown
summaries are generated from those files, with paired seed differences reported
separately from image-bootstrap intervals. The latter do not establish patient
independence. Any publication table must identify the metric grid and evaluation
cohort. Do not mix original-grid and 192-pixel pilot scores.
